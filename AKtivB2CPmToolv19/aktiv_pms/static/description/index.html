Overview

Now, we can manage all the Projects and Tasks on which different users are working.

Features

View the Projects and Tasks.

View Projects assigned to managers

View Task assigned to the users.

View status of the Tasks and Projects.

View Communication Plans.

View Test Cases per task updated by QA.

Make Quality Checks for the task done by developer.

Setup & Configuration

Prerequisites

  • Required Apps

    No prerequisites or Apps are required before the installation.

Configuration

Enable the 'Project Manager' Rights or 'Administrator' Rights from Settings to provide access to the module's features, and full rights to the project which will enable to create, edit and delete project and tasks.

Any user with the 'Project QA' Rights can access the project or task in which the user is assigned as a QA and create and edit the test cases.

Any user with the 'User' Rights can only access the projects and tasks in which they are assigned but cannot edit the project hence only has the right to edit their timesheet only.

Screenshots

List view of all projects: It will include name of project, customer, project manager, status, total planned hours, total remaining hours and total invested hours in the project.

List view of all tasks: Here the title, project, developers, hours spent, progress and state of the task.

When the Project Manager or Administrator is creating the project these fields basic customer information, developer, code reviewer and QA fields present in Project information tab will be mandatory and the project type field to know the type of project.

Now, the tasks will be created by the Project Manager that will be assigned to the developers that are related to the project. If the project type is consulting then the task created will have the type as consulting, hence functional description will be mandatory, and the task will only have two states. When task is created it will be in new state and then be moved to done state.

If the project type is customization then the task create will also be of type customization, hence the technical description will be visible and mandatory and the task will contain all the states.

When task is sent for code review a popup will be show to check the quality checks and then move the task to next state.

When task is in Code review state, the code reviewer will add the notes and can send the task for Redevelopment if required or send for QA Testing.

When task is in QA testing state, the QA will be able to add the test cases and can send for redevelopment if bugs or send for customer review.
